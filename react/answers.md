## Вопрос 1. В чем разница между функциональными и классовыми компонентами в React? Когда следует использовать каждый тип?
Функциональные компоненты – это обычные функции, принимающие props и возвращающие JSX. С появлением хуков они получили состояние и побочные эффекты, стали основным и рекомендуемым способом написания компонентов. Классовые компоненты – это классы, наследующие React.Component, с методами жизненного цикла и this.state. Функциональные компоненты короче, легче читаются и тестируются, хуки позволяют переиспользовать логику без HOC и render props. Классовые компоненты всё ещё встречаются в старых кодовых базах и нужны дляError Boundary (до появления хуков для этого не было замены). Практический совет: новый код писать на функциональных компонентах с хуками; классовые использовать только для поддержки legacy-кода или если нужен componentDidCatch.

## Вопрос 2. Что такое props и state? Как они отличаются и какие правила их использования?
Props (properties) – это данные, передаваемые в компонент извне, от родителя. Они доступны только для чтения: компонент не должен их мутировать. State – это внутреннее состояние компонента, которым он управляет сам, и изменение state вызывает повторный рендер. Ключевые отличия: props приходят снаружи и неизменяемы внутри компонента; state принадлежит компоненту и изменяется через setState (классы) или функцию-сеттер из useState (функции). Правила: props не мутировать, а передавать новые значения от родителя; state обновлять иммутабельно (новый объект/массив, а не мутация), не дублировать props в state без необходимости, поднимать состояние вверх, если оно нужно нескольким компонентам.

## Вопрос 3. Как работает поднятие состояния (lifting state up) и в каких ситуациях это необходимо?
Поднятие состояния – перенос state из дочерних компонентов в их ближайший общий родительский компонент, чтобы синхронизировать или координировать их поведение. Шаги: удалить state из детей, передать данные из родителя через props, добавить state в родителя и передать вниз обработчики для его изменения . Необходимо, когда два или более компонента должны разделять одно и то же состояние (например, только одна панель аккордеона открыта одновременно, или выбранный элемент в списке влияет на детали справа). Это также принцип «единственного источника истины»: для каждого кусочка state выбирается компонент-владелец, обычно ближайший общий предок.

## Вопрос 4. Какие методы жизненного цикла классовых компонентов вы знаете и для чего они используются?
Основные фазы: монтирование, обновление, размонтирование. Методы монтирования: constructor (инициализация state и привязка методов), render (возврат JSX, должен быть чистым), componentDidMount (побочные эффекты после вставки в DOM: запросы, подписки). Обновление: shouldComponentUpdate (оптимизация, возврат false предотвращает рендер), render, componentDidUpdate(prevProps, prevState) (реакция на изменения после обновления DOM). Размонтирование: componentWillUnmount (очистка: отмена таймеров, отписки, удаление обработчиков). Устаревшие и небезопасные методы (UNSAFE_componentWillMount, UNSAFE_componentWillReceiveProps, UNSAFE_componentWillUpdate) не рекомендуется использовать в новом коде . В функциональных компонентах аналог большинства из них – useEffect (и useLayoutEffect для синхронных операций до отрисовки).

## Вопрос 5. Как работают хуки useState и useEffect? Какие правила использования хуков существуют?
useState(initialValue) возвращает пару [state, setState]: текущее значение и функцию обновления, которая планирует повторный рендер. Если новое значение вычисляется из предыдущего, используют функциональное обновление setState(prev => ...). useEffect(callback, deps) выполняет побочный эффект после рендера: без массива зависимостей – после каждого рендера; с [] – один раз после монтирования (и очистка при размонтировании); с [dep] – при изменении dep. Возвращаемая из callback функция – это cleanup, выполняемая перед следующим запуском эффекта или при размонтировании. Правила хуков: вызывать только на верхнем уровне функционального компонента или кастомного хука; не вызывать внутри условий, циклов, вложенных функций, после раннего return, в обработчиках событий, в классах, в try/catch/finally . Порядок вызовов хуков должен быть одинаковым при каждом рендере – на этом основана работа React. Для проверки используют eslint-plugin-react-hooks.

## Вопрос 6. Что такое ключи (keys) в React и почему они важны при рендеринге списков?
Ключи – это специальный строковый или числовой атрибут, который нужно задавать элементам внутри массива (обычно в map), чтобы React мог идентифицировать каждый элемент среди соседей . Они важны, потому что React использует ключи при согласовании (reconciliation): чтобы понять, какие элементы добавлены, удалены, перемещены или изменены. Хороший ключ – стабильный и уникальный ID из данных (например, id из базы). Индекс массива как ключ допустим только в крайнем случае, если список статичен и не меняет порядок; при вставке/удалении/сортировке это приводит к путанице состояния и лишним рендерам . Нельзя генерировать ключи на лету (Math.random(), Date.now()) – это вызывает полный ремоунт списка при каждом рендере . Ключи не передаются в компонент как prop; если нужно значение внутри, передайте его отдельным prop.

## Вопрос 7. Как обрабатывать события в React и чем это отличается от нативного JavaScript?
Синтаксис: обработчики в React пишутся в camelCase (onClick, onChange) и передаются как функции, а не строки, в JSX . Нельзя вернуть false для отмены поведения по умолчанию – нужно явно вызывать event.preventDefault() . React использует SyntheticEvent – кроссбраузерную обёртку над нативным событием, соответствующую спецификации W3C; обычно не нужно беспокоиться о совместимости браузеров. Не нужно вручную вызывать addEventListener: обработчик указывается при рендере элемента. В классовых компонентах нужно привязывать this для методов-обработчиков (bind в конструкторе или стрелочные поля класса), иначе this будет undefined . В функциональных компонентах этой проблемы нет; для передачи параметров используют стрелочную функцию или bind: onClick={() => handle(id)} или onClick={handle.bind(null, id)}.

## Вопрос 8. Что такое управляемые и неуправляемые компоненты? В чем их разница?
Управляемый компонент – это компонент, значение которого контролируется React state: например, value input берётся из state, а onChange обновляет state. Родитель полностью управляет поведением через props . Неуправляемый компонент хранит своё состояние внутри DOM (как обычный HTML-элемент), а React обращается к нему через ref, когда нужно прочитать значение. Управляемые компоненты дают полный контроль (валидация на лету, условная блокировка, форматирование ввода), но требуют больше кода. Неуправляемые проще в настройке, меньше ре-рендеров, но менее гибкие при координации. На практике компонент может сочетать оба подхода; выбор зависит от того, насколько важно контролировать значение из React.

## Вопрос 9. Как работает контекст (Context) в React и когда его следует использовать?
Context позволяет передавать данные глубоко по дереву компонентов, не прокидывая props через каждый промежуточный уровень . Три шага: создать контекст через createContext(defaultValue), обернуть часть дерева в Provider с value и читать значение в любом потомке через useContext(Context) . Контекст ищет ближайший Provider выше по дереву; если его нет, используется defaultValue. Использовать, когда данные нужны многим компонентам на разных уровнях и их передача через props становится громоздкой: тема оформления, текущий пользователь, локаль/язык, настройки. Не стоит использовать контекст для всего подряд: это усложняет переиспользование компонентов и отслеживание зависимостей; для простых случаев props остаются предпочтительнее. Для обновления контекста комбинируют с state в родителе и передают сеттер или само значение через Provider.

## Вопрос 10. Какие преимущества предоставляют кастомные хуки и как создавать собственные хуки?
Кастомный хук – это функция, имя которой начинается с use и которая вызывает другие хуки внутри. Он позволяет вынести повторяющуюся логику с состоянием и эффектами из компонентов в переиспользуемую функцию, не меняя иерархию компонентов . Преимущества: переиспользование логики (а не UI), чистота компонентов, единое место для сложных эффектов, возможность тестировать логику отдельно. Создание: объявить функцию useSomething, внутри использовать useState/useEffect/другие хуки, вернуть нужные значения или функции. Пример: useData(url) инкапсулирует fetch с состоянием загрузки и ошибки, возвращает data; компоненты вызывают его и получают данные без дублирования эффекта . Важно: кастомный хук должен следовать правилам хуков, называться с use и решать конкретную задачу, а не быть обёрткой-пустышкой над useEffect.
